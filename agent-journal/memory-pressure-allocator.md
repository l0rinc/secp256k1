Hypothesis and trust boundary:

Repeated `CCoinsViewCache` clear/flush/reset operations might retain pool
chunks without reporting them, or might make `DynamicMemoryUsage()` drift from
the actual retained allocation. A cache-size decision could then undercount
memory during block, reorg, snapshot, or fuzz workloads. The trust boundary is
the local chainstate/cache implementation; the direct callers are block
connect/disconnect, snapshot loading, replay, and cache tests, not arbitrary
network bytes. This is distinct from the already audited standalone
`PoolResource` lifecycle campaign and from network queue memory.

Source and history evidence:

- `src/support/allocators/pool.h:21-36, 203-265` documents that pool chunks
  are owned until resource destruction and that freed blocks return to
  freelists; `Allocate` and `Deallocate` retain chunk capacity by design.
- `src/coins.cpp:38-40` computes cache usage from the map's pool chunks plus
  inner `Coin` usage. `src/memusage.h:199-216` counts the pool resource's
  allocated chunks, chunk size, list-node estimate, and bucket array.
- `src/coins.cpp:260-270` clears entries and only reconstructs the resource
  when `reallocate_cache` is true. `src/coins.cpp:322-330` performs that full
  resource reset. `src/coins.cpp:283-289` intentionally reuses capacity on
  `Reset`.
- `src/test/coins_tests.cpp:957-965` explicitly documents that a pool-backed
  cache's memory need not decrease after erasing entries, and asserts that
  usage does not increase. `:1088-1110` checks that the resource is used and
  remains fully accounted for after map destruction.
- `src/validation.cpp:2942`, `:3097`, `:3215`, and `:5081` show the live
  choices between full cache flush/reallocation and small temporary caches
  that deliberately retain a one-block footprint.
- Blame identifies the current parameter semantics at `3e0fd0e4ddd` (2026-01-29).
  History `5e4ac5abf5` introduced explicit reallocation because pool-backed
  `clear()` does not release memory; the later conditional form preserves
  reuse where the caller has a bounded cache.
- Core commit `7ebd0c7962` already performed a separate PoolResource
